## 7. Intervention-hook mechanics — **PASS, with strong empirical validation**

Code-level checks (`70_intervention.py`, `src/awake/eval/causal.py`):

1. Only the subject's last subword at the hooked point is replaced ✓
   (`t[0, subject_last] = …`); no other position mutated ✓
2. Only the intended point is patched (one hook per forward, removed in `finally`) ✓
3. Orthogonal component preserved for the direction-only patch — the formula
   `h' = h_r + (u·h_d − u·h_r)u` is exact, and `patch_changes_only_projection` /
   `test_direction_patch_replaces_only_the_projection` / `test_patch_changes_only_projection_detects_orthogonal_leak` lock it ✓
4. Hook points (embedding / block_i / ln_f) are the same modules the baseline cache
   extracts from — residuals patched are the same points cached ✓
5. In-place mutation targets freshly computed module outputs (GPT-NeoX layer outputs are
   new tensors each forward; no aliasing into persistent buffers) ✓
6. Hook removal guaranteed via `try/finally` ✓
7. Donor residuals come from the same per-stimulus caches at the same points ✓
8. C2 random: Gram–Schmidt orthogonal unit vectors, deterministic seeds
   (`seed = s·1000 + index(p)`), norm-matched per example to the primary patch norm
   (`‖Δ_random‖ = ‖Δ_number‖`); K=3 seeds all retained, pooled as within-lemma rows
   (not treated as independent clusters) ✓

**Decisive empirical evidence.** The pre-registered architectural prediction is exact:
a subject-position patch at `block_11`/`ln_f` has no downstream route to a *later*
prediction position. Independently recomputed from raw rows: near/attractor effects at
`block_11` and `ln_f` are **0.000000 for all 6,480 items** (min = max = 0), while
`simple` (subject == prediction position) is 1.191/0.935. This pattern cannot arise from
a misplaced hook, a leaked patch, or an off-by-one token position. Combined with bitwise
C0 on all splits, the hook semantics are validated beyond what any unit test could show.

## 10. H3 specificity / controls — **MIXED: H3 not formally tested (Concern A)**

- **C0 no-op:** bitwise reproduction on all splits ✓
- **C1 same-number:** |E| ≤ 0.015 at every layer; embedding CI [−0.033, 0.002] includes
  zero ✓; interpretation as magnitude/donor-variability control is fine (it is *not*
  claimed to be norm-matched) ✓
- **C2 random:** correct construction (unit, orthogonal, norm-matched per example,
  K=3 deterministic seeds, pooled within-cluster) ✓. But the effects are **not**
  literally zero (Concern B): several 95% CIs exclude zero — embedding 0.033
  [0.026, 0.039], block_5 0.066 [0.061, 0.072], block_11 −0.0002
  [−0.00025, −0.00010], among others. "Controls at zero" / "do not move the contrast
  toward the donor number" is over-categorical. The magnitudes are tiny relative to the
  primary effect (≤0.066 vs 4.84 at the embedding ≈ 1.4%), and the small positive bias is
  consistent with nonlinear degradation of the subject representation — defensible
  wording: "random-direction effects are much smaller than the primary number-direction
  effect, but are not identically zero."
- **C3 full-residual:** positive at every layer (6.42 → 0.72), all CIs above zero on the
  matched-tokenization subset (6,960 items vs 7,200) ✓. Population difference is
  acknowledged in the report ("on the matched-tokenization subset") ✓.
- **H3 as pre-registered** ("stronger donor-directed shift than no-op, same-number, and
  norm-matched random-direction transfer") is **not computed** by `80_causal_eval.py`:
  it computes per-condition CIs vs zero only. The report's "The effect is
  **direction-specific** (H3 supported)" therefore rests on an informal comparison, not
  a formal contrast. The informal evidence is very strong (4.84 vs ≤0.066 at every layer,
  with per-item pairing available), but the pre-registered H3 statistic should be
  computed. **Repair (analysis only, no GPU):** per layer, paired
  `E_number − E_same` and `E_number − mean_seed(E_random)` at the item level, with
  lemma-cluster bootstrap CIs, from the cached rows. All per-example outputs already
  exist (`rows.parquet`).

**Conclusion sentence audit:** the snapshot's `conclusion` string is generated whenever
the primary CI excludes zero and appends "relative to no-op, same-number, and
norm-matched random-direction controls" as fixed text — the "relative to" clause is the
ADR's pre-registered allowed language, but it is not currently backed by the computed
statistics. Once the paired contrasts are added (they will surely pass), the sentence
becomes fully supported.
